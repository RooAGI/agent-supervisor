# Agent Supervisor 0.1.1

This release publishes the core `agent-supervisor` crate on crates.io and
keeps the OpenShell integration as a separate developer preview.

## Added

- The core `agent-supervisor` crate is available on crates.io as version
  `0.1.1`, licensed under Apache-2.0.
- An experimental OpenShell adapter lives in `dev/openshell-adapter/`. It runs
  one-shot commands in an existing OpenShell sandbox using NVIDIA's Rust SDK.
  It is not included in the published core crate because NVIDIA currently
  distributes the Rust SDK from Git rather than crates.io.
- OpenShell contract documentation describes bounded collection, validation,
  deadlines, structured failures, and remote termination limits.

## Changed

- `ExecutableIdentity::canonical_path` is now `Option<PathBuf>`. Native
  execution continues to provide the verified canonical path; the developer
  adapter reports `None` because OpenShell does not return the resolved
  executable path. Callers reading this field should handle the optional value.
- The developer adapter rejects per-command filesystem restrictions, disabled
  networking, required enforcement, kernel resource limits, host environment
  inheritance, and local executable search paths when the remote API cannot
  apply or verify those requirements.
- The adapter uses a fresh request ID and a local wait deadline. If a stream
  ends, overflows, or times out without an observed exit event, the remote
  command's final state is unknown. Closing the stream does not prove process
  termination. OpenShell's remote timeout is surfaced as an exit code and
  cannot be distinguished from a command returning that code itself.
- README, quickstart, and the documentation site now describe the crates.io
  release and separate developer adapter.

## Compatibility

The `canonical_path` type change is a source-level API change for users who
read that field. The published core crate has no OpenShell SDK dependency; its
default native API remains usable through the normal crates.io dependency.
The adapter is an unpublished developer package and requires an OpenShell SDK
Git checkout dependency.

## Validation

The core test suite passed on macOS. The separate adapter unit tests passed,
and a local Docker OpenShell sandbox smoke test successfully executed
`/bin/echo` through the adapter. Platform-specific Linux and Windows
integration tests still need to run on their respective operating systems.
